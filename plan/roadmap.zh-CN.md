## 已确定的边界

- Python >=3.12。
- 新代码放在根目录 tallyjudge，src/ragas 原位保留。
- 单包内插件；核心不依赖外部框架 SDK。
- 新命名统一。
- 可视化工具采用 Streamlit，在独立仓库维护，暂不排期。界面通过 TallyJudge 的公开 Python 接口查询指标、绑定数据列、运行评测并读取结果。Streamlit 依赖由界面仓库管理。
- 每个阶段只新增必要文件，不预建所有插件空目录。

## 单轮 RAG 的三个功能版本

第一个大目标是让已有 RAG 系统稳定迁到新包。验收覆盖三种数据条件。只有问题、回答和检索上下文时能评回答质量，有标注上下文或文档 ID 时能评检索，有参考答案时能评回答正确性。下表按依赖排序，版本号和发布渠道在发布验收时确定。

| 功能版本 | 必交能力 | 可以复验的结果 |
|---|---|---|
| 第一版 · 回答质量（阶段 2，本地已验收） | `FaithfulnessMetric` 使用裁判模型，`AnswerRelevanceMetric` 复用裁判并通过嵌入比较问题。两者都从 `Evaluator.arun` 运行 | 同一数据集导出两项得分及失败原因。三段提示词在固定环境与旧版一致，零向量为无定义，超时或取消保留已知用量。仓库外安装默认 wheel 可用假客户端跑通。 |
| 第二版 · 检索质量（阶段 2b） | 复用裁判迁移有参考和无参考两种 ContextPrecision 及 ContextRecall。对有文档 ID 的数据迁移 `IdContextPrecisionMetric`、`IdContextRecallMetric` | 有参考版读 `reference`，无参考版读 `response`。按排名判定 `[1,0,1]` 的平均精度为 `5/6`。ID 路径在无模型环境评分，检索 ID `["B","A","A"]` 对参考 ID `["A","C","D"]` 应得精度 `1/2`、召回 `1/3`。空分母状态逐例登记。 |
| 第三版 · 参考答案正确性（阶段 2b） | 先迁移 `SemanticSimilarityMetric`，再迁移 `AnswerCorrectnessMetric`，复用首版的嵌入、陈述生成和模型协议 | 分别验证相似度阈值 `None` 与 `0.0`、单侧空陈述、事实与相似度加权。相似度权重为零时只注入裁判即可评分。 |

每项指标都要从旧提交 `ec00339` 取得固定输入和输出，核对分数、状态和有意差异。三个版本合起来还需通过一次公开入口验收。从同一套数据按指标所需字段绑定，逐行导出九个指标的结果，保留失败样本和覆盖率。默认安装保持轻量，迁移说明逐项标出已验证能力与差异。真实供应商端点另列实测记录。[阶段 2 实现清单](phase-2.zh-CN.md#11-分批实施与退出标准)

实体召回、事实细粒度评分、噪声敏感度以及 `AnswerAccuracy`、`ContextRelevance`、`ResponseGroundedness` 仍在后续迁移清单，按实际使用场景逐项补充。非 LLM 文本距离、HHEM 和框架接入沿用扩展阶段安排。Prompt、工作流、Agent 评测以及独立 Streamlit 界面保留各自的路线。[指标能力与来源](plugin-architecture.zh-CN.md)

## 阶段 0 遗留项

- **首版安装与回归**。阶段 1 的本地提交已包含代码、独立可运行的迁移测试和 `py.typed`。首版构建仍需要纳入工作区中的根 `pyproject.toml` 和 CI 配置。
- **版本号**：setuptools_scm 当前继承 ragas 的 v0.4.x tag，生成的版本为 0.4.4.devN。对外分享任何构建产物之前，要定下 tag 策略（例如新包只匹配 `tallyjudge-v*`，并设置 fallback 版本）。release 工作流会把产物上传到 GitHub Release，需要一并检查。
- **仓库外安装已验证**。默认 wheel 已在干净环境从 site-packages 导入并完成两个本地指标和两个 RAG 指标的评分。发布检查还需核对 sdist 的文件清单，当前 sdist 仍收录 `src/ragas/`、旧测试、文档和示例。构建后端也提示需要在发布前更新许可证的 TOML 写法。[阶段 2 验收](phase-2.zh-CN.md#本轮验收记录)
- **原实现分析文档**：当前工作区已无根目录 ARCHITECTURE.zh-CN.md，本轮未重建；原实现的调用链与能力来源继续参考总设计，阶段 1 的实际验收见阶段文档。

## 每个迁移单元的记录

| 字段 | 内容 |
|---|---|
| 来源 | 原文件/符号、提交或上游 PR |
| 目标 | 新文件/符号、稳定插件 ID |
| 操作 | 新增 / 复制迁移 / 改名 / 契约重构 / 新包不收录 |
| 行为 | 保留公式与参数；列出有意差异（包括输入校验变化）及评分 revision |
| 依赖 | 所需第三方包、是否按需加载、支持的 Python 与平台 |
| 验证 | 上游提交、固定输入与预期行为、故障场景、测试结果及待验证的集成 |
| 文档 | 当前状态、示例、安装组与迁移说明 |

一次提交围绕一个可解释的行为或边界，命名调整与公式变更尽量分开。借用上游代码时保留出处，不把全部上游分支直接合入新包。

## 检查顺序

1. 在 `ec00339` 的独立旧环境取得固定输入的分数、异常及空值行为。需要重查时让工具输出到临时目录。[阶段 1](phase-1.zh-CN.md)
2. 在 Python 回归测试中直接声明输入和预期行为，逐项说明与上游的有意差异。
3. 验证缺少无关 SDK 时，仍可导入并使用已选能力。
4. 检查结果身份、绑定 key、配置快照和评分版本是否足以重建这次运行。
5. 更新能力表与 README 状态，未完成的工作继续标为计划。

阶段结束时，只扩大已经证明可用的支持范围。生产用户路径中不展示内部迁移的实现细节；这里的设计说明面向贡献者。
